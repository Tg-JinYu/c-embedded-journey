## 学习日志 - 2026.10.12

### ✅ 实现功能
- 实现了 `my_strcpy` 功能，代码文件：`my_strcpy.c`

### 🧠 知识点总结
- **替身指针（`char *p = result`）**：深刻理解了指针操作的底层逻辑。`p` 只是复制了 `result` 的地址，`p++` 改变的是 `p` 自己的指向，而 `*p = *ch` 改变的是 `result` 所指向的那块内存空间的内容。
- **标准库函数规范**：手写标准库函数时，参数顺序和返回值类型应尽可能与标准库保持一致。
  - `strcpy(result, ch)`：目标字符串 `result` 在前，源字符串 `ch` 在后。
  - 返回值为 `char *`：为了支持链式调用，应返回未被修改的 `result` 首地址。
- **字符串结束符**：使用 `while` 循环复制时，必须手动在目标字符串末尾追加 `\0`，否则打印时会导致内存越界。

### 🚧 踩坑记录
- **返回值类型错误**：函数定义时写成了 `char my_strcpy(...)`，返回 `char *` 时会导致地址（8字节）被截断为单字符（1字节）。已修正为 `char *my_strcpy(char *result, const char *ch)`。

## 学习日志 - 2026.10.13

### ✅ 实现功能
- 实现了 `my_strcmp` 功能，代码文件：`my_strcmp.c`
- 实现了 `my_strncmp` 功能，代码文件：`my_strncmp.c`

### 🧠 知识点总结

#### 1. my_strcmp（字符串比较）
- **核心原理**：`strcmp` 比较的不是“长度”，而是**字典序（ASCII 码值）**。从左往右逐个字符比较，遇到不同字符或 `\0` 就停止。
- **返回值规则**：返回 `*str1 - *str2`。
  - 遇到 `\0` 同时结束，返回 `0`（完全相等）。
  - 遇到不同字符，返回它们的 ASCII 差值（正数表示 str1 大，负数表示 str1 小）。
- **循环终止的边界**：`*str1 == *str2` 负责“继续比较”，`*str1 != '\0'` 负责“安全刹车”。在 `*str1 == *str2` 成立的前提下，只要 `*str1 != '\0'`，`*str2` 必定也不为 `\0`，因此不需要额外判断 `*str2 != '\0'`。
- **短路求值**：`&&` 是从左到右执行的，一旦某个条件为假，后面的条件不会再判断。

#### 2. my_strncmp（限定长度字符串比较）
- **与 strcmp 的区别**：加了一个 `n`，最多只比较前 `n` 个字符。
- **循环退出的三种情况**：
  1. 遇到 `\0`（字符串结束）。
  2. 遇到不相同的字符（分出大小）。
  3. `n` 耗尽（`i == 0`，前 `n` 个字符完全相等）。
- **n 耗尽时必须特殊处理**：循环结束后必须先判断是否因为 `n` 耗尽退出，而不能无脑返回 `*str1 - *str2`。

### 🚧 踩坑记录
- **n 耗尽时的越界比较**：初版 `my_strncmp` 在循环退出后无条件执行 `return (*str1 - *str2)`。当 `n = 3` 比较 `"apple"` 和 `"app"` 时，`n` 耗尽退出，但 `str1` 指向 `'l'`，`str2` 指向 `\0`，导致错误地返回了正数，与标准库返回 `0` 不符。
- **修复方案**：在循环结束后、返回差值之前，加入 `if (i == 0) return 0;` 判断，确保前 `n` 个字符完全相等时直接返回 `0`，避免越界比较不属于前 `n` 个字符范围内的内容。

## 学习日志 - 2026.10.14

### ✅ 实现功能
- 实现了 `my_strcat` 功能，代码文件：`my_strcat.c`
- 实现了 `my_strstr` 功能，代码文件：`my_strstr.c`

### 🧠 知识点总结

#### 1. my_strcat（字符串拼接）
- **指针遍历与内存写入**：使用替身指针 `p` 遍历 `dest` 找到末尾，再逐个把 `src` 的字符写入 `p` 所指向的内存。因为 `p` 和 `dest` 指向同一片物理内存，所以对 `*p` 的修改直接反映在 `dest` 数组中。
- **首地址保护**：`dest` 本身不移动，移动的只是 `p`，这样最后 `return dest;` 才能返回正确的字符串首地址，支持链式调用。
- **结束符处理**：拼接完成后必须手动在末尾补上 `\0`。

#### 2. my_strstr（查找子串）
- **双重循环与回溯**：查找子串需要两层循环。外层由 `p1_start` 控制尝试匹配的起点；内层由 `p1` 和 `p2` 逐字符比较。
- **三个指针的角色分工**：
  - `p1_start`：记录本轮匹配的主串起点，失败后 `p1_start++` 向后滑动。
  - `p1`：主串探路者，每轮开始时重置为 `p1_start`。
  - `p2`：子串探路者，每轮开始时重置为 `p2_start`（子串开头）。
- **提前返回**：当 `p2` 指向 `\0` 时，说明子串完全匹配成功，直接返回 `p1_start`。
- **空子串边界**：如果 `p2` 一开始就是 `\0`，标准库规定返回主串的开头 `p1`。

### 🚧 踩坑记录
- **my_strcat 初版指针越界**：初版误将 `dest` 本身也进行了 `dest++`，导致最后返回的是字符串末尾地址而非首地址；且画蛇添足地调用了 `strcpy(dest, p)`，把刚拼接好的数据截断了。
- **my_strstr 初版无法回溯**：初版只用两个指针，匹配失败后无法回到当前起点的下一个位置重新开始；修复方案是引入 `p1_start` 和 `p2_start` 记录起点，并在外层循环每次开始时重置探路指针。
- **my_strstr 内层循环死循环**：曾误将 `p1 = p1_start; p1++;` 放在内层循环里，导致 `p1` 在起点和起点+1之间反复横跳，无法向后推进。
- **const 限定符警告**：函数返回类型为 `char *`，而返回的是 `const char *`（`p1_start`），编译时产生 `-Wdiscarded-qualifiers` 警告，通过 `(char *)` 强制类型转换解决。

## 学习日志 - 2026.10.15

### ✅ 实现功能
- 实现了 `my_memcpy` 功能，代码文件：`my_memcpy.c`
- 实现了 `my_memmove` 功能，代码文件：`my_memmove.c`

### 🧠 知识点总结

#### 1. my_memcpy（内存拷贝）
- **void 与字节操作**：`memcpy` 接收 `void *dest` 和 `const void *src`，不关心数据类型。为了逐字节拷贝，需要将其强制转换为 `char *` 和 `const char *`，使指针 `++` 一次刚好移动 1 个字节。
- **size_t 循环变量**：参数 `n` 类型为 `size_t`（无符号整数），循环变量也使用 `size_t`，避免了有符号与无符号比较的编译警告。
- **性能优化**：在函数开头加入 `if(n == 0 || dest == src) return dest;`，处理零拷贝和自身拷贝的边界情况，避免无意义的内存操作。

#### 2. my_memmove（内存移动，支持重叠）
- **与 memcpy 的核心区别**：`memcpy` 不处理内存重叠，而 `memmove` 必须处理。
- **内存重叠的处理策略**：
  - 当 `pDest < pSrc`（目标在左边）：正序拷贝，安全且高效。
  - 当 `pDest > pSrc`（目标在右边）：倒序拷贝。先将 `pDest` 和 `pSrc` 定位到指定拷贝区域的末尾（`+ n - 1`），然后通过 `*pDest-- = *pSrc--` 从后往前拷贝，避免源数据被提前覆盖。

### 🚧 踩坑记录
- **指针赋值与解引用混淆**：在倒序拷贝初始化指针时，误写成了 `*pDest = (char *)dest + n - 1;`。
  - `*pDest = ...` 试图把地址赋值给 1 字节的字符，不仅类型不匹配，还会因为 `pSrc` 是 `const` 类型而报“只读内存赋值”的错误。
  - 修复方案：去掉等号左边的星号，改为 `pDest = ...`，即改变指针变量自身的指向，而不是它指向的内存数据。
- **const 指针赋值规则**：巩固了 `char *` 可以赋值给 `const char *`（权限收缩），但 `const char *` 不能赋值给 `char *`（权限放大）。

## 学习日志 - 2026.10.17——2026.10.18：环形缓冲区

### ✅ 实现功能
- 实现了完整的环形缓冲区（Ring Buffer），文件结构分为 `ring_buffer.h` 和 `ring_buffer.c`。
- 提供了初始化的 `rb_init`、判空 `rb_is_empty`、判满 `rb_is_full`、写入 `rb_write` 和读取 `rb_read` 五个核心接口。

### 🧠 知识点总结
- **缓冲区的存在意义**：协调生产者和消费者的速度差（如串口中断接收与主循环处理），实现软硬件解耦，防止数据丢失。
- **指针绕圈原理**：利用取模运算 `(tail + 1) % capacity`，让指针在数组末尾自动回到 0，无需搬移底层数据，时间复杂度达到 O(1)。
- **传参设计**：写操作传值（数据源），读操作传指针（带走数据）。底层接口不应打印日志，应通过返回值（0 或 -1）让调用者决定如何处理异常。
- **数据类型**：使用 `uint8_t` 处理字节流，字符的底层本质就是 ASCII码，利用不同的输出格式可以输出字符本体或者其对应的ASCII码（%c->字符；%d->ASCII码）。

### 🚧 踩坑记录
- **判空逻辑的“防御性陷阱”**：初版 `rb_is_empty` 中，为了做防御性编程，检查了 `rb->capacity == 0` 和 `rb->buffer == NULL` 的情况并返回 `-1`。但最后却错误地直接 `return 1;`，导致无论缓冲区实际有没有数据，只要初始化参数正常，就永远被判定为“空”。
- **修复方案**：保留防御性检查，但最终的核心状态判断必须回归真实数据量，即检查 `rb->count == 0`，从而正确返回布尔状态。

## 学习日志 - 2026.10.19 ~ 2026.10.20：单链表模块

### ✅ 实现功能
- 实现完整的单链表模块，结构体采用**数据域与指针域分离**的设计（`linked_list.h` / `linked_list.c`）。
- 核心接口：`list_init`、`list_create_node`（动态分配+防御检查）、`list_insert_tail`（尾插法）、`list_find_node`、`list_delete_node`（处理删头/中/尾及未找到情况）、`list_print`、`list_free`。

### 🧠 核心知识点与设计总结
- **二级指针的运用**：需要修改外部头指针指向时（如空链表插入、删头节点、清空），必须传 `list_node_t **head`；若只修改节点内部或节点间的联系，传一级指针即可。
- **双指针遍历删除法**：单链表无前驱指针，删除节点时必须用 `prev` 记录前驱。通过 `prev->next = curr->next;` 绕过当前节点。
- **内存安全防范**：在 `list_free` 中，严格遵循**“先保存下一节点地址，再释放当前节点”**的原则，杜绝 Use-After-Free；释放完毕后置空头指针，防止悬空指针。
